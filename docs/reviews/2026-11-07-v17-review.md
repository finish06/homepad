## Findings

### 1. [Fixed] The #441 StrictMode tests fail on Node 26 — the spy targets the wrong object

`src/grid/tileDensity.server.test.ts` spied on `Storage.prototype.setItem`, but on
Node 26+ the Web Storage shim (`src/test/setup.ts`) installs a standalone
`MemoryStorage implements Storage` class whose `setItem` never passes through
`Storage.prototype`. The spy therefore counted **0** writes and two tests failed:

```
#441 — set() persists exactly once, even under StrictMode
  a change writes the device cache once and PATCHes the server once   expected 1, got 0
  two quick changes persist each value once, in order                 expected 2, got 0
```

This is environment-specific: CI runs Node 22, where jsdom's real `Storage` makes
the prototype spy work. It contradicts `docs/cicd.md`'s "the shim makes the suite
runnable on 26" claim. Fix: spy on the **instance** (`vi.spyOn(localStorage,
'setItem')`), which counts identically on both runtimes. The assertion's intent —
exactly one cache write, no extra PATCH under StrictMode — is unchanged. Verified
`1175/1175` after the change, including the two tests.

### 2. [Low] AccountsSection's Retry loses its cancellation guard

`src/accounts/AccountsSection.tsx` uses `useEffect(() => load(), [load])`, where
`load()` returns a `live = false` cleanup. That works for the effect, but the
Retry button calls `load` directly and discards the cleanup, so a retry that
outlives the panel can still `setState`. React 18 makes this harmless in
practice; the pattern is just uneven. Prefer an `AbortController` or a single
`live` ref owned by the component.

### 3. [Low] Creating a kid and saving their apps are two calls — the failure state is honest but leaves a half-built kid

`src/accounts/KidEditor.tsx` `save()` creates the kid (`POST /api/admin/kids`),
then replaces the allow-list (`PUT …/services`). If the first succeeds and the
second fails, the kid exists with no apps and `onSaved` has already updated the
list behind the modal. The copy says exactly that ("Saved Maya, but couldn't save
their apps"), the editor stays open, and retry re-sends only the app list — so
nothing is lost or misreported. Worth knowing rather than fixing: the two
endpoints cannot be one transaction from here. A cheaper improvement would be to
defer `onSaved` until the app-list write settles, so the row never appears before
it is complete.

### 4. [Advisory] Focus containment relies on `trapTab`, not `inert`

`src/ui/trapTab.ts` wraps Tab at the layer's first/last control. It does not pull
focus back if focus is outside the layer, and the page beneath is not `inert`.
In practice both kid modals move focus inside on open (Cancel / the name field)
and dismiss on scrim click, so this is adequate — but it is a softer guarantee
than `aria-modal="true"` implies. Consider `inert` on the app root while a
portalled dialog is open (would also help the existing TileEditModal).

### 5. [Info] Membership sync compares ids only

`src/services.tsx` `sameMembers` replaces the list when the **set of ids**
changes. A catalog reorder or section rename does not remount a kid's grid
(`key={kid-${membershipVersion}}`), so it shows on the next load, not the next
poll. That matches AC-002's wording ("an admin ticked or unticked an app"), and
keeping the v13 identity-and-order merge for everyone else is the right call.

### 6. [Info] The security boundary is not in this repo

Everything the kid shell hides (edit mode, Library, Admin Panel, tile edit) is
also refused server-side per the spec (§7), but that enforcement and the two
migrations (`0017` sessions, `0018` kid role) live in `homepad-api` and were not
reviewed here. The frontend does the right thing regardless: it gates on
`role === 'kid'`, not on missing data, so it never offers an action that would
403.

## What is solid

- **Role gating is structural, not cosmetic.** `isKid` drives the header, menu,
  grid, health panel, toasts and alert history; the kid branch of `UserMenu` is a
  separate render path, not a pile of `hidden` classes.
- **Defensive reads.** `jsonOrThrow` + `arrayOrThrow` reject a 200 with the wrong
  shape instead of handing a non-array to `.map` (the comment records the exact
  unmount that motivated it), and `kidServices` distinguishes `null` (empty list)
  from a missing key (error) so the editor can never save `[]` over a list it
  failed to read.
- **The #441 setter fix is correct.** `useTileDensity` now short-circuits on a
  synchronous ref rather than doing side effects inside the state updater — this
  is what makes the StrictMode double-invoke tests meaningful, and it is why
  finding 1 was worth fixing rather than deleting.
- **Test depth is appropriate to the risk.** AccountsSection (231 lines),
  KidEditor (711), kid shell, status bar, user menu, device formatting, plus
  browser gates for the admin flow and the iPad board.
- **The dangerous action is treated as dangerous.** "Sign in this device as …" is
  a separate alertdialog, Cancel takes initial focus, the primary button names
  the kid, and the session swap happens server-side followed by a reload — no
  admin state is left in memory.
