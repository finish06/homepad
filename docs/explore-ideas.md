# Homepad — Explore Ideas

Dated product ideas for future consideration. Not specs — just prompts for later discussion.

---

- **2026-06-14 — Idea #2:** Mini uptime sparkline on each tile, showing the last N check results as a compact dot-strip (green/red), plus a rolling uptime percentage (e.g. "98% / 20 checks"). *Prompted by: `homepad-api/internal/gatus/poller.go` `FetchAll()` already receives Gatus's full `results[]` array (20 historical checks per endpoint) on every poll but only reads the last result and discards the rest — the history is free to use.* The sparkline would make the status badge far more informative (is a DOWN blip one flap or a multi-hour outage?) at zero extra network cost, since the data is already in each poll response.

- **2026-06-14 — Idea #3:** Add a "Recently launched" section at the top of the Command Launcher's empty-query list, backed by a client-side localStorage ring buffer of the last 5 service IDs you've opened — a zero-API-change extension of the pattern already used for the theme and collapse caches. *Prompted by: `src/CommandLauncher.tsx` `activateSelected()` fires the link and closes the dialog but records nothing, while `buildSections()` constructs the empty-query state purely from `s.favorite` — so every Cmd+K session starts from the same static Favorites → All order regardless of what you actually launch daily.*

- **2026-06-14 — Idea #4:** Show the service description as a second line in each Command Launcher result row so users can see *why* a search result appeared. *Prompted by: `src/ranker.ts` ranks description at weight 0.4 (after name and category), so a query can surface a result solely via its description — but `ResultRow` in `src/CommandLauncher.tsx` never renders `service.description`, leaving the user staring at a result they can't explain, even though the description string is already in the payload and is shown on the catalog tile.*

- **2026-06-14 — Idea #5:** Add a distinct "Not monitored" tile state (separate from UNKNOWN) for services with no Gatus key set, since `statusFor()` in `homepad-api/internal/api/services.go` currently collapses both an empty `gatus_key` and a Gatus-returned unknown into the same gray badge — leaving users unable to tell whether a tile is simply unwired from monitoring or whether monitoring genuinely can't reach the service. *Prompted by: `services.go` `statusFor()` returns `StatusUnknown` for both cases identically.* A small "unmonitored" chip or dash indicator would make the launcher an active guide to observability gaps, prompting users to connect a Gatus key rather than silently rendering every unconfigured tile as if monitoring had failed.

- **2026-06-14 — Idea #6:** When a user adds an app from the Library, auto-file it into the user's matching category (case-insensitive name match on the offer's `suggestedCategory`) instead of always landing in Uncategorized — a pure backend change in `store.AddFromLibrary` that queries the user's own categories for a name hit before defaulting to NULL. *Prompted by: `LibraryBrowse.tsx:85` calls `addFromLibrary(offer.id)` with no `categoryId`, while `handleAddFromLibrary` in `library.go` already accepts an optional `categoryId` body param — the `suggestedCategory` chip is rendered in the browse dialog but silently discarded at add time, so every library add requires a manual drag to the right section even when the user already has an identically-named category.*
